# 实时车位问题分流设计

## 背景

用户询问“南京医科大学附属泰州人民医院现在还有多少空车位”时，请求没有命中现有地图停车流程，而是进入医院挂号知识库。根因是地图停车入口只识别“停车场、停车、车停”，没有识别“空车位、剩余车位、停车位”等常见表达。

## 目标

- 医院语境中的“空车位、剩余车位、停车位、车位”问题进入现有高德地图停车流程。
- 继续复用现有医院候选确认和附近停车场查询，不新增第二套停车实现。
- 高德未提供实时余位时，明确显示“实时车位未知”，不推断或编造数量。
- 非医院语境中的普通“车位”消息不应误触发医院停车流程。

## 方案

扩展 `careguide.map_parking_chat.EXPLICIT_PARKING` 的停车表达，使 `MapParkingChatService.matches()` 能识别医院实时车位问题。同步扩展查询清洗规则，避免把“现在还有多少空车位”拼进医院 POI 关键词。

API 仍在通用 Agent 之前执行确定性的地图停车分流。首次请求搜索并展示医院候选；用户确认医院后，调用现有高德停车场查询。停车候选继续使用 `available_spaces=None` 表达实时余位未知。

## 验收标准

1. “南京医科大学附属泰州人民医院现在还有多少空车位？”命中 `map_parking`，不调用通用医疗 Agent。
2. 高德医院搜索关键词不包含“空车位、剩余车位”等尾部问题。
3. 选择医院后的停车候选不伪造可用车位数量。
4. “小区车位怎么分配”不命中医院停车分流。
5. 现有停车查询与 API 测试继续通过。
