# CareGuide 对话 Agent 接入高德停车设计

日期：2026-10-30

## 1. 目标

让用户在 CareGuide 对话页直接查询真实医院停车信息。例如输入“查询泰州医院停车场”时，系统应调用高德地图医院搜索，而不是进入预约工作流或医疗知识库。

当医院名称存在多个匹配项时，系统必须向用户展示真实院区列表并等待选择，不自动选择第一项。用户确认院区后，系统查询该院区周边停车场，并可跳转到现有“行程重规划”页面查看地图。

## 2. 非目标

- 不获取或推断实时剩余车位；
- 不把普通步行路线标记为轮椅可通行；
- 不在真实查询失败时回退到 SIM-A/B/C；
- 不通过医院名称自动执行预约操作；
- 不在本阶段实现停车预约、支付或医院内部导航。

## 3. 路由优先级

在普通 Agent 规划前增加确定性的真实停车意图处理器。满足以下条件时进入该处理器：

- 文本包含停车相关意图，如“停车场”“停车”“开车去医院”；
- 同时包含医院、院区或就医地点表达；
- 文本不是明确要求运行 SIM 模拟重规划的请求。

处理顺序为：

1. 真实医院停车查询处理器；
2. 已有明确模拟约束的停车演示处理器；
3. 普通 Agent 编排。

真实停车查询不得进入旧预约工具、医疗 RAG 或合成医院工具。

## 4. 对话状态

### 4.1 首次查询

用户输入医院名称后，后端调用 `AmapClient.search_hospitals`，返回规范化院区候选。

- 无候选：返回 `no_results`，建议补充城市或正式医院名称；
- 一个候选：仍展示候选并要求用户确认，避免名称相近造成误选；
- 多个候选：展示所有候选的名称、地址、城市和高德 POI 标识。

### 4.2 用户选择

候选项必须绑定当前用户、会话、查询和有效期。前端提交结构化选择事件，包含：

- 当前会话 ID；
- 查询 ID；
- 被选择的高德医院 POI ID；
- 候选版本。

后端只能接受本次候选列表中的 POI ID，不接受前端任意提供的新坐标或医院对象。

### 4.3 停车结果

确认院区后，后端通过 POI 详情和周边检索获得停车候选，返回：

- 医院院区；
- 停车场名称、地址、坐标、入口、类型及距离；
- `available_spaces: null`；
- `wheelchair_accessible: null`；
- `data_tier: map_poi`；
- 来源与查询时间；
- 用于前端打开地图页的结构化上下文。

## 5. 后端组件

新增独立的 `MapParkingChatService`，职责为：

- 识别窄范围的真实停车查询；
- 提取医院查询文本和城市提示；
- 调用 `AmapClient`；
- 管理短期院区候选状态；
- 校验用户的结构化选择；
- 生成对话响应和完整 trace。

该服务不依赖大模型，不执行医疗判断，也不负责渲染地图。高德鉴权、超时和数据规范化继续由 `AmapClient` 负责。

候选状态优先复用现有工作流存储或业务 SQLite 存储，记录查询 ID、用户、会话、候选 POI ID、版本和过期时间。不得仅依赖浏览器提交的医院数据。

## 6. API 与响应契约

`POST /chat` 和 `POST /chat/stream` 继续作为统一入口。请求可携带新的结构化地图事件：

```json
{
  "kind": "map_hospital_select",
  "query_id": "...",
  "candidate_version": 1,
  "hospital_id": "B0..."
}
```

候选响应增加：

```json
{
  "intent": "map_parking",
  "workflow_status": "waiting_user",
  "map_selection": {
    "query_id": "...",
    "candidate_version": 1,
    "hospitals": []
  },
  "simulation": false
}
```

停车结果增加：

```json
{
  "intent": "map_parking",
  "workflow_status": "completed",
  "map_parking": {
    "hospital": {},
    "candidates": [],
    "data_tier": "map_poi"
  },
  "simulation": false
}
```

所有错误响应不得包含高德服务端 Key、完整外部请求 URL 或未经校验的外部错误正文。

## 7. 前端交互

对话消息中的院区候选以按钮列表显示：

- 名称；
- 地址；
- 城市/行政区；
- “高德地图 · map_poi”来源标识。

用户点击院区后，前端提交结构化选择事件，不把按钮文字重新作为自然语言发送。

停车结果以摘要列表显示，并提供“在地图中查看”按钮。点击后：

1. 切换到“行程重规划”；
2. 进入真实地图模式；
3. 注入已确认的医院与停车候选；
4. 地图绘制标记；
5. 用户仍需显式选择停车场后才请求路线。

## 8. 真实性与安全边界

- 对话响应和地图页统一使用 `map_poi` 真值等级；
- `available_spaces` 未经授权实时来源时始终为 `null`；
- `wheelchair_accessible` 未经静态核验时始终为 `null`；
- 普通步行路线保持 `wheelchair_verified=false`；
- 真实查询响应不得出现 `SIM-` ID；
- 模拟查询不得接受 `map_poi` 候选；
- 候选选择必须校验用户、会话、版本和有效期；
- 后端 Key 不进入响应、trace、日志或前端构建。

## 9. 错误处理

- 未配置 Key：明确返回 `provider_unconfigured`；
- 高德鉴权失败：返回 `provider_auth_failed`；
- 超时或限流：显示可重试提示，保留当前对话；
- 医院无匹配：要求补充城市或正式名称；
- 候选已过期：要求重新查询，不复用旧 POI；
- 停车场无结果：保留已确认院区，允许扩大搜索范围；
- 地图加载失败：对话中的停车场文字列表仍可使用。

## 10. 测试与验收

后端测试覆盖：

- “查询泰州医院停车场”进入地图处理器而非预约工具；
- 多院区候选返回并等待选择；
- 明确医院仍要求确认真实院区；
- 非候选 POI、跨用户、跨会话、旧版本和过期选择被拒绝；
- 确认后返回真实停车候选且未知字段保持 `null`；
- 无结果、鉴权失败、超时和限流不生成模拟数据；
- trace 记录地图工具输入但不包含 Key。

前端测试覆盖：

- 候选按钮提交结构化选择事件；
- 真实结果显示来源、时间和未知状态；
- “在地图中查看”正确切换并注入状态；
- 真实对话结果不出现 SIM-A/B/C；
- 地图失败时文字结果仍保留。

验收场景：

1. 输入“查询泰州医院停车场”；
2. 页面显示多个高德院区候选；
3. 选择“南京医科大学附属泰州人民医院”；
4. 对话返回真实停车场列表；
5. 点击“在地图中查看”；
6. 地图页定位医院及候选；
7. 页面持续显示“实时车位未知、无障碍通行未核实”。
