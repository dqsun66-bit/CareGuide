# CareGuide 江苏 15 家医院官方知识库设计

## 1. 目标

为 CareGuide 建立第一版可追溯、可复核、可更新的江苏医院就医导航知识库。知识库覆盖 15 家三级甲等医院，重点回答医院及院区识别、预约挂号、就诊准备、报告查询、交通停车、无障碍服务和官方联系方式等问题。

本阶段的核心产物是经过来源登记、清洗、去重、分块和质量审核的结构化语料。资料核验通过后，再由华为 Embedding 生成向量、写入 Chroma，并使用华为 Rerank 参与混合检索。本阶段不要求调用付费模型。

知识库提供就医导航信息，不提供诊断、处方、药物剂量或替代医生判断的临床结论。

### 2.2 每家医院的资料类别

1. 医院身份、等级、正式名称、别名和主管关系；
2. 院区名称、地址、主要功能及院区区别；
3. 预约、挂号、取号、退号、改约、停诊和爽约规则；
4. 科室、普通门诊、专病门诊、急诊及官方门诊安排说明；
5. 就诊及检查前准备，包括证件、医保和医院明确发布的注意事项；
6. 检验、影像、病理等报告的官方查询或领取方式；
7. 公共交通、停车入口、院内通行和无障碍服务；
8. 官方咨询电话、服务时间、发布日期和复核日期。

### 2.3 不在本阶段范围内

- 医生个人排班的实时同步；
- 号源余量、实时停车余位或院内定位；
- 从非官方问答、百科、商业挂号站复制医疗事实；
- 根据症状推断疾病或给出处方；
- 自动发布未经审核的抓取结果；
- 华为 Embedding、Rerank、Chroma 建库和 AgentArts 接入。

高德地图可在运行时提供地点、路线和周边停车场搜索，但不得覆盖医院官方发布的院区和入口事实。

## 3. 来源政策

### 3.1 来源优先级

按以下顺序选择来源：

1. 医院官方网站中的现行患者服务页面、公告和正式指南；
2. 国家、省、市卫生健康主管部门或政府网站；
3. 医院认证的官方微信公众号文章；
4. 政府或医院指定的官方预约平台；
5. 高德地图等地图服务，仅用于地点检索和路线信息。

搜索结果摘要只能用于发现页面，不能直接进入知识库。第三方百科、商业健康平台、新闻转载和开放研究语料不得作为医院规则的最终证据。

### 3.2 来源登记

每个来源页面必须记录：

- `source_id`；
- 页面标题与规范化 URL；
- 官方域名和来源层级；
- 所属医院及院区；
- 内容类别；
- 页面发布日期或更新时间；
- 采集时间与最近复核时间；
- HTTP 状态、正文哈希和快照路径；
- 审核状态及审核说明。

URL 中的跟踪参数和无意义锚点必须移除。相同正文由多个 URL 提供时，保留权威性最高且最稳定的规范 URL。

## 4. 数据布局

```text
data/jiangsu_hospitals_v1/
├── README.md
├── manifest.json
├── hospitals.json
├── sources.json
├── records.json
├── verification.json
└── snapshots/
    └── <hospital_id>/
        └── <source_id>.<html|pdf|md>
```

- `README.md`：数据用途、生成方式、安全边界和复核流程；
- `manifest.json`：语料版本、构建时间、记录数量、来源数量和内容哈希；
- `hospitals.json`：医院、院区、别名和官方域名；
- `sources.json`：官方来源登记表；
- `records.json`：可供 BM25 和后续向量化使用的知识片段；
- `verification.json`：冲突、过期、缺失和人工审核结果；
- `snapshots/`：用于复核和变更检测的原始页面快照。

运行时检索不得实时抓取医院网页。网页变化通过独立更新流程处理，审核后才生成新语料版本。

## 5. 数据模型

### 5.1 医院与院区

```json
{
  "hospital_id": "js_taizhou_003",
  "official_name": "泰州市第二人民医院",
  "aliases": ["泰州二院", "姜堰人民医院"],
  "city": "泰州",
  "hospital_type": "general",
  "grade": "三级甲等",
  "grade_source_id": "src_tz_001",
  "official_domains": ["jyry.com"],
  "campuses": [
    {
      "campus_id": "js_taizhou_003_main",
      "official_name": "总院",
      "address": "江苏省泰州市姜堰区健康路27号",
      "address_source_id": "src_tz_002"
    }
  ]
}
```

医院等级和地址均必须通过 `source_id` 追溯。多个院区不得合并为一个无院区标识的地址。

### 5.2 知识片段

```json
{
  "document_id": "js_taizhou_003_appointment_0001",
  "hospital_id": "js_taizhou_003",
  "campus_id": "js_taizhou_003_main",
  "city": "泰州",
  "category": "appointment",
  "title": "门诊预约挂号规则",
  "content": "经过清洗并保留完整语义的事实段落",
  "source_id": "src_tz_010",
  "source_url": "https://www.jyry.com/",
  "source_tier": "hospital_official",
  "published_at": "2026-01-10",
  "collected_at": "2026-11-04T12:00:00+08:00",
  "reviewed_at": "2026-11-04T15:00:00+08:00",
  "review_status": "verified_official",
  "content_hash": "sha256:be9e9ccc4cb3b95c2d5a1d500c237322abb3feb4c6106a00bca40169e83e4879",
  "language": "zh-CN"
}
```

时间使用 ISO 8601 格式并带 `+08:00` 时区。页面没有发布日期时，`published_at` 为 `null`，不得用采集日期冒充发布日期。

## 6. 采集与处理流程

```text
医院清单与官方域名核验
        ↓
来源发现与 sources 登记
        ↓
页面抓取、快照与正文哈希
        ↓
正文提取及导航/广告/页脚清理
        ↓
医院、院区、类别和标题归一化
        ↓
精确去重与近似去重
        ↓
语义分块与元数据补全
        ↓
来源、时效和冲突审核
        ↓
只发布 verified_official 记录
        ↓
BM25 离线索引与固定问题集验证
```

第一批按泰州市人民医院、泰州市中医院、泰州市第二人民医院的顺序处理。流程验证通过后再扩展到其余 12 家医院。

## 7. 清洗、去重与分块

### 7.1 清洗

删除站点导航、版权页脚、推荐阅读、分享按钮、广告、重复侧栏和无内容的模板文字。保留标题层级、编号列表、表格行、办理步骤、重要提示和院区限定语。

禁止通过大模型补写缺失事实。OCR 或页面提取不确定的文本标记为 `needs_review`，不得发布。

### 7.2 去重

去重分三层：

1. 规范 URL 和正文哈希完全相同时精确去重；
2. 去除日期、导航等模板后，对正文做近似重复检测；
3. 对同一规则的多个官方版本按发布日期、来源层级和适用院区人工判定。

转载页面不得因为 URL 不同而形成多个相同知识片段。旧版规则保留在快照和核验记录中，但不进入当前可检索记录。

### 7.3 分块

分块顺序为：医院 → 院区 → 类别 → 标题 → 完整事实段落。

- 目标长度为 250～600 个中文字符；
- 相邻片段可保留 50～80 个字符的语义重叠；
- 一组办理步骤、注意事项或表格行必须保持完整；
- 一个片段不得混合两个医院或两个适用规则不同的院区；
- 过短片段优先与同标题下相邻内容合并；
- 过长片段只在自然段、列表组或小标题边界切分。

## 8. 审核状态与发布规则

审核状态固定为：

- `verified_official`：官方来源、事实完整且核验通过；
- `needs_review`：来源可信但存在提取、院区或适用范围疑问；
- `expired`：明确失效、被新版本替代或超过复核期限；
- `conflict`：两个官方来源对同一事实存在不一致。

只有 `verified_official` 可以进入用户可见检索。`needs_review`、`expired` 和 `conflict` 只能出现在维护界面或验证报告中。

当不同官方页面冲突时，系统不得自动选择对用户更便利的说法。应保留两份来源证据、标记冲突，并由人工根据页面日期、主管部门公告或医院确认结果解决。

## 9. 时效与更新

预约规则、门诊时间、入口、停车和联系方式属于易变信息，默认复核周期不超过 90 天；医院身份、等级和历史信息默认不超过 365 天。页面若明确给出有效期，以页面有效期为准。

更新流程比较 URL、正文哈希和关键字段：

- 无变化：更新检查时间，不生成新记录；
- 内容变化：进入 `needs_review`，审核后发布新语料版本；
- 页面失效：寻找同一官方域名中的替代页面，未找到时标记 `expired`；
- 医院改名或院区调整：保留旧别名用于查询，但所有当前记录迁移到新的正式实体。

不得在不更新 `manifest.json` 版本和内容哈希的情况下覆盖已发布语料。

## 10. 与检索和华为模型的边界

本语料首先支持现有 BM25 检索。通过固定问题集和人工抽检后，后续流程为：

```text
verified_official records
        ↓
华为 Embedding 批量生成向量
        ↓
版本化 Chroma 集合
        ↓
BM25 Top-K + 向量 Top-K
        ↓
RRF 融合去重
        ↓
华为 Rerank
        ↓
来源、时效和相关性安全门
```

向量索引必须绑定语料版本和内容哈希。语料改变后旧索引不得继续标记为当前版本。华为模型不可用时可以降级为 BM25，但不能宣称混合检索已启用。

## 11. 错误处理与安全边界

- 找不到官方来源：该事实缺失，不使用第三方内容补齐；
- 页面依赖登录、验证码或小程序：登记来源但不绕过访问控制，寻找公开官方替代资料；
- PDF/OCR 失败：保留快照并标记 `needs_review`；
- 院区不明确：不得写入通用院区，等待核验；
- 只有地图结果：可用于实时路线候选，不得写成医院官方停车规则；
- 资料过期或冲突：用户侧回答“当前没有已核验的现行规则”；
- 医疗问题超出导航范围：交给安全分诊流程，不让医院知识库给出诊断或治疗建议。

采集日志、快照和语料不得包含真实患者信息、API 密钥、Cookie 或登录令牌。

## 12. 测试与质量验收

### 12.1 结构验证

- JSON 文件可解析并符合固定 schema；
- `hospital_id`、`campus_id`、`source_id` 和 `document_id` 唯一；
- 每条记录都能追溯到一个登记来源；
- 所有医院等级和院区地址都具有来源；
- 只有允许的审核状态进入发布集合；
- 内容哈希、语料版本和清单统计一致。

### 12.2 内容质量抽检

每家医院至少人工抽检：

- 2 条医院/院区资料；
- 2 条预约或门诊规则；
- 1 条报告查询；
- 1 条交通、停车或无障碍资料；
- 1 条联系方式或服务时间。

抽检要求为医院归属正确、院区明确、事实与来源一致、无正文截断、无错误拼接、无第三方断言。

### 12.3 检索验证

为每家医院建立至少 5 个固定问题，覆盖别名、院区、预约、报告和交通。第一版至少形成 75 个问题。验证指标包括：

- Top-5 是否召回正确医院和类别；
- 回答证据是否来自 `verified_official`；
- 同名或别名是否路由到正确医院；
- 多院区问题是否避免跨院区混答；
- 没有证据时是否明确拒绝猜测。

本阶段以 BM25 结果建立基线。华为混合检索接入后使用同一问题集对比 Recall@5、MRR、来源合格率和错误院区率。

## 13. 验收标准

1. 15 家医院均有唯一实体、正式名称、城市、类型、三甲证据和官方域名；
2. 每个实际纳入的院区均有独立 `campus_id` 和官方地址来源；
3. 语料包含 60～100 个官方来源页面和约 300～600 个知识片段；
4. 所有发布记录均为 `verified_official`，并可追溯至快照和官方 URL；
5. 精确重复记录为零，近似重复和官方冲突均有核验结果；
6. 75 个以上固定问题完成 BM25 基线评测；
7. 检索不到可靠资料时系统拒绝猜测；
8. 当前语料不包含患者隐私、密钥、Cookie 或非官方医疗事实；
9. 语料版本和内容哈希可供后续 Chroma 索引强校验；
10. 泰州 3 家医院先通过完整流程验收，再批量扩展其余医院。

## 14. 实施分解

本设计拆分为四个顺序阶段：

1. 建立 schema、目录、验证器和泰州 3 家医院清单；
2. 采集并审核泰州官方来源，形成首批记录和 BM25 评测；
3. 按相同流程扩展其余 12 家医院并完成全量质量报告；
4. 在独立计划中接入华为 Embedding、Chroma 和华为 Rerank。

每个阶段均以可复核的数据文件和自动化验证为完成条件，不以“抓取成功”作为完成标准。
