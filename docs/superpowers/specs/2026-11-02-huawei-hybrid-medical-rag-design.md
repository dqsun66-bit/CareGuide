# CareGuide 华为混合医疗 RAG 与安全分诊设计

## 目标

将 CareGuide 当前的 BM25 单条召回升级为可验证的华为 ModelArts MaaS 混合检索链路，并修复“头痛咨询召回孕酮资料”“要求患者自行填写科室”等错误。系统必须先进行医疗安全分流，再使用经过来源、相关性和时效性过滤的证据生成回答。

## 范围

本设计包含：

- 华为 Embedding 与 Rerank API 适配；
- 本地 Chroma 版本化向量索引；
- BM25 与向量 Top-K 召回、RRF 融合、去重和 Rerank；
- 查询改写、否定描述保护、来源等级与最低相关度安全门；
- 头痛场景的确定性危险信号分流和科室建议；
- 检索可观测性、明确降级和回归评测。

本设计不包含在线诊断、处方、药物剂量决策、代替医生问诊，以及把用户病情写入知识库或 Chroma。

## 总体数据流

```text
用户输入与最近对话
        ↓
症状结构化解析
        ↓
确定性医疗安全门
        ↓
上下文查询改写与否定词保护
        ↓
┌─────────────────┬──────────────────┐
│ BM25 Top 20     │ 华为向量 Top 20 │
└─────────────────┴──────────────────┘
        ↓
RRF 融合与 document_id 去重
        ↓
华为 Rerank Top 10
        ↓
来源等级、相关度、时效性与否定冲突过滤
        ↓
Top 3～5 证据交给回答模型
        ↓
分诊建议、观察事项、科室建议与证据说明
```

## 组件设计

### 1. 症状上下文与查询改写

查询构造器从当前输入和最近用户对话中提取症状、起病时间、严重程度、部位、伴随表现、明确否定、外伤和特殊人群信息。当前输入只有“请判断是否紧急并告诉我挂什么科”时，必须补入同一会话中最近明确的症状；历史中也没有症状时，只允许追问，不启动开放语料检索。

否定描述作为结构化约束保留。例如“没有肢体无力”可以用于排除危险信号，但不得因为包含“肢体无力”而提高脑卒中文档的相关性。用于 Embedding 的自然语言查询与用于安全门的结构化事实分开保存。

### 2. 医疗安全门

安全门在 RAG 之前运行。头痛至少覆盖以下危险信号：

- 突然发生并迅速达到高峰的剧烈头痛；
- 新发肢体无力或麻木、面歪、语言障碍、意识异常、抽搐；
- 高热并伴颈部僵硬、畏光或不褪色皮疹；
- 近期头部外伤后出现或加重的头痛；
- 视力突然丧失；
- 用户明确表示症状快速恶化或无法安全等待。

命中危险信号时返回急诊分流，不等待 RAG 提供结论。信息不足时返回需要补充的临床问题，不创建要求患者填写 `department` 的预约任务。

### 3. 华为模型服务适配器

Embedding 使用 ModelArts MaaS/OpenAI 兼容向量接口；Rerank 使用 ModelArts MaaS 重排序接口。密钥、端点和模型名只从环境变量读取：

- `CAREGUIDE_EMBEDDING_API_KEY`
- `CAREGUIDE_EMBEDDING_BASE_URL`
- `CAREGUIDE_EMBEDDING_MODEL`
- `CAREGUIDE_RERANK_API_KEY`
- `CAREGUIDE_RERANK_BASE_URL`
- `CAREGUIDE_RERANK_MODEL`

客户端必须设置连接/读取超时、有限重试、输入条数和长度上限。异常信息不得包含 Authorization、完整请求正文或用户病情。代码、测试夹具、trace 和 Git 历史不得包含真实密钥。

### 4. 版本化 Chroma 索引

Chroma 只保存知识片段文本、向量和以下元数据：`document_id`、`corpus_version`、`content_hash`、`kind`、`source_id`、`source_tier`、`hospital_id`、`department`、`valid_until`。

索引集合名绑定知识库版本和内容哈希。启动时若集合不存在、维度不匹配或哈希不一致，混合检索标记为不可用，不得自动建立伪向量索引，也不得继续使用过期集合。建立或重建索引必须由显式脚本完成。

用户消息、会话历史、手机号、身份信息和病情不得写入 Chroma。

### 5. 混合召回与 Rerank

- BM25 召回 20 条；
- 向量检索召回 20 条；
- 使用带权 RRF 合并，并按 `document_id` 去重；
- 将最多 20 条融合候选提交 Rerank；
- 保留 Rerank 前 10 条进入安全过滤；
- 最终最多提供 3～5 条证据给回答模型。

所有 K 值由有界配置控制，但 Agent 不得再把 `search_care_guidance` 强制改成 `top_k=1`。检索响应必须记录 BM25 数量、向量数量、融合数量、Rerank状态、过滤原因和最终证据数量。

### 6. 证据安全过滤

来源分为：

1. 监管机构、国家/地方卫健机构；
2. 医院官方页面和正式患者指南；
3. 经过明确审核的公共健康资料；
4. 开放研究语料，例如 KUAKE、Huatuo26M-Lite。

开放研究语料不能单独支持急诊结论、诊断、处方、药物剂量或保胎等高风险建议。检索结果必须同时满足相关度阈值、来源适用范围和有效期。无合格证据时返回“未找到足够可靠资料”，不得选择最高分结果强行作答。

### 7. 科室建议

分诊模块根据结构化症状给出有限建议：一般轻度头痛且无危险信号可建议全科或普通内科初评；反复、持续或需要专科评估时可考虑神经内科；危险信号对应急诊。该映射是就医导航，不是诊断。

用户明确要求预约时，推荐出的科室才可作为后续预约任务输入。普通“挂什么科”咨询不得转换成要求用户自己填写科室的 `waiting_input` 任务。

## 降级与错误处理

- Embedding 不可用：可降级为 BM25，但响应必须显示 `retrieval_mode=bm25_degraded`，并执行更严格的来源与相关度过滤；
- Rerank 不可用：只允许高等级来源且通过更高阈值的证据，否则拒答；
- Chroma 索引缺失或版本不匹配：不自动重建，明确报告索引不可用；
- 安全门命中：立即给出急诊分流，不因外部模型失败而延迟；
- 无症状上下文：追问症状，不运行通用 RAG；
- 外部模型返回格式错误、超时或限流：记录脱敏错误代码，向用户返回安全、可恢复的状态。

系统不能把任何降级模式标记为“混合检索成功”。

## 前端与可观测性

对话结果和最近 trace 展示：

- 安全分流状态；
- 运行中的检索模式；
- BM25、向量、融合、Rerank和最终证据数量；
- 是否发生降级；
- 证据来源等级和未审核提示。

前端不显示密钥、上游完整错误、向量内容或内部提示词。

## 验收标准

1. “头有点疼”先追问起病、程度和危险信号，不直接检索随机资料。
2. “头痛，但没有肢体无力”不得把脑卒中资料因“肢体无力”关键词而提升为主要证据。
3. “突然出现一生中最严重的头痛”在不调用 RAG 的情况下返回急诊分流。
4. “请判断是否紧急并告诉我挂什么科”在缺少症状上下文时追问，不返回孕酮资料。
5. 混合模式的 trace 显示 BM25 和向量召回、RRF、Rerank以及最终证据计数。
6. 无关候选全部低于阈值时返回资料不足。
7. Embedding、Rerank或 Chroma 分别失效时，降级状态真实且可测试。
8. 一般轻度头痛且无危险信号时，输出观察事项和有限科室导航，不声称诊断。
9. 知识库文件变化后，旧向量索引被拒绝使用。
10. 自动化测试不调用付费模型；真实联调脚本需要显式密钥和显式执行。

## 测试策略

- 单元测试：症状结构化、否定词、危险信号、RRF、阈值、来源过滤、科室建议；
- 契约测试：华为 Embedding/Rerank 请求和响应格式、超时、限流、脱敏；
- 集成测试：BM25 + 假向量集合 + 假 Reranker 的完整混合链路；
- API测试：JSON/SSE 返回相同的安全分流和检索元数据；
- 浏览器测试：头痛多轮追问、危险信号、无关资料拒答及检索状态展示；
- 真实验证：使用显式 ModelArts 凭据构建版本化索引并运行固定查询集，不在 CI 中执行。

## 完成定义

只有在版本化向量索引成功建立、真实华为 Embedding/Rerank 验证通过、固定头痛场景回归通过、前端正确显示混合检索状态且无密钥泄漏后，才能宣称“混合检索 + Top-K + Rerank 已完成”。缺少华为凭据时，可以完成代码与离线测试，但必须将真实联调标记为未完成。
