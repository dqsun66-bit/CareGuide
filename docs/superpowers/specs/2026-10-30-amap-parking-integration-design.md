# CareGuide 高德停车与地图接入设计

日期：2026-10-30

## 1. 目标

在现有 CareGuide 网页应用中加入高德真实地点与路线能力，将“真实地图数据”和“模拟停车变化”严格分开：

- 使用高德 Web 服务 API 搜索医院、院区和周边停车场，并计算驾车与步行路线。
- 使用高德 Web 端 JS API 在 Vue 页面展示医院、停车场、入口和路线。
- 保留现有 SIM-A/B/C 事件重规划演示，但只能在独立的模拟模式中出现。
- 不把地图 POI 推断为实时车位、无障碍车位或已核实轮椅路线。

本阶段不接入医院停车运营系统，不声称提供实时车位或院内无障碍导航。

## 2. 方案选择

采用“后端高德 Web 服务 + 前端高德 JS API + 确定性规划器”的组合方案。

未选择仅后端列表方案，因为用户明确需要交互地图。未选择 HarmonyOS 原生客户端方案，因为现有产品是 Vue 网页与 Python 后端，本阶段重写客户端会扩大范围且不能直接解决停车数据真实性问题。

## 3. 数据可信等级

每条数据必须携带 `data_tier`、来源和时间信息：

| 等级 | 含义 | 可用于什么 | 不可声称什么 |
| --- | --- | --- | --- |
| `map_poi` | 高德返回的地点、地址、坐标、入口或普通路线 | 候选地点、地图标记、外部道路路线 | 实时空位、无障碍可达 |
| `verified_static` | 医院官方资料、授权访谈或现场核实 | 已核实停车入口、落客点、静态无障碍设施 | 超出核实时间和范围的实时状态 |
| `live_authorized` | 医院、停车运营方或政府平台授权接口 | 带时间戳的实时车位与状态 | 超过有效期后的实时状态 |
| `simulation` | 程序虚构测试数据 | 演示事件驱动重规划 | 真实医院服务或导航建议 |

当 `available_spaces` 没有 `live_authorized` 来源时必须为 `null`，界面显示“实时车位未知”。当轮椅通行没有 `verified_static` 来源时必须显示“无障碍通行未核实”，不能从普通步行路线推断。

## 4. 密钥和配置

后端 Web 服务 Key 仅保存在服务端配置中：

- `CAREGUIDE_AMAP_WEB_SERVICE_KEY`

前端 JS API Key 通过单独的公开构建变量提供：

- `VITE_AMAP_JS_KEY`

后端 Key 不得进入前端构建产物、API 响应、日志或 trace。前端 Key 按高德 Web 端 Key 的使用方式加载，并在高德控制台配置允许的域名；本地开发域名和正式演示域名分别管理。

## 5. 后端组件

### 5.1 `AmapClient`

建立独立高德客户端，职责仅包括：

- 文本搜索医院或院区；
- 周边搜索停车场；
- 获取 POI 地址、坐标、入口、停车类型；
- 请求驾车和步行路线；
- 将高德错误转换为 CareGuide 的结构化错误。

客户端设置明确超时，不依赖 SDK 隐式重试，不记录 Key。外部响应先校验再转换为内部模型。

### 5.2 停车候选服务

输入为院区标识、搜索半径和可选用户位置，输出统一的停车候选：

- `parking_id`
- `name`
- `address`
- `location`
- `entrance_location`
- `parking_type`
- `distance_to_hospital_m`
- `walking_route`
- `available_spaces: null`
- `wheelchair_accessible: null`
- `data_tier: map_poi`
- `source_provider: amap`
- `observed_at`

排序可以参考距离，但不能把未知车位或未知无障碍条件当成满足条件。

### 5.3 API

增加只读接口：

- `GET /map/hospitals/search?q=...&city=泰州`
- `GET /map/hospitals/{hospital_id}/parking?radius_m=...`
- `POST /map/routes`

保留 `POST /demo/parking/replan`，但响应继续标记 `simulation: true`。真实地图接口不接受模拟车位事件。

## 6. 前端交互

“行程重规划”页面增加模式切换：

1. **真实地图模式**
   - 搜索并确认院区；
   - 显示医院和周边停车场标记；
   - 点击候选查看地址、停车类型、距离和来源；
   - 绘制普通驾车或步行路线；
   - 固定显示“实时车位未知”和“无障碍通行未核实”，除非以后接入相应可信来源。

2. **模拟重规划模式**
   - 保留 SIM-A/B/C 和车位变化事件；
   - 使用醒目的模拟数据提示；
   - 不与真实地图候选混合排序或合并展示。

地图加载失败时，停车场列表仍可使用；后端搜索失败时，不回退到 SIM 数据冒充真实结果。

## 7. 数据流

1. 用户输入“泰州市人民医院”并选择院区。
2. 前端请求后端医院搜索接口。
3. 后端用 Web 服务 Key 调用高德并返回规范化医院候选。
4. 用户确认院区后，后端搜索周边停车场并按来源规则返回。
5. 前端 JS API 绘制医院和停车场标记。
6. 用户选择停车场后，请求路线接口并绘制路线。
7. 页面展示数据来源、查询时间和真实性限制。

## 8. 错误与安全处理

- 缺少后端 Key：返回 `provider_unconfigured`，不发出外部请求。
- 高德鉴权失败：返回 `provider_auth_failed`，不暴露高德原始 Key 或请求签名。
- 限流或暂时不可用：返回可重试错误和简短用户提示。
- 无搜索结果：提示调整院区或搜索半径，不生成虚构停车场。
- 路线不可用：仍展示 POI，但明确路线未生成。
- 外部响应字段缺失：保留 `null`，禁止补默认车位或无障碍结论。
- 前端 Key 只用于地图展示；后端 Key 永远不进入浏览器。

## 9. 测试策略

### 后端

- 使用 MockTransport 验证高德请求参数和响应转换。
- 测试医院搜索、停车场搜索、路线规划、空结果、超时、鉴权失败和限流。
- 测试响应中没有后端 Key。
- 测试未知实时车位和无障碍属性保持 `null`。
- 保留现有停车模拟测试，确保真实模式不会返回 SIM-A/B/C。

### 前端

- 测试地图模式与模拟模式严格隔离。
- 测试地图加载失败时列表仍可使用。
- 测试来源、查询时间、车位未知和无障碍未核实提示。
- 测试选择停车场后请求并展示路线。

### 现场验证

- 使用真实 Key 搜索“泰州市人民医院总院”。
- 查看周边停车场候选和入口字段。
- 选择一个候选并生成普通路线。
- 确认页面没有显示虚构剩余车位或轮椅可通行结论。

## 10. 验收标准

- 能搜索并定位泰州市人民医院院区。
- 能展示高德返回的周边真实停车场候选。
- 能在交互地图中显示医院、停车场和所选路线。
- 后端 Key 不出现在浏览器、响应、日志或 trace 中。
- 没有授权实时数据时，车位状态明确为未知。
- 没有核实资料时，无障碍状态明确为未核实。
- SIM-A/B/C 仅出现在模拟模式。
- 后端和前端新增测试通过，现有测试不回归。

## 11. 非目标

本阶段不包括：

- 获取或猜测医院实时剩余车位；
- 声称普通步行路线适合轮椅；
- 构建 HarmonyOS 原生客户端；
- 接入收费、预约或停车交易；
- 批量扩展全国医院。
