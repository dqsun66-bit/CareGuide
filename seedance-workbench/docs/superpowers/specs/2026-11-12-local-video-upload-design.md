# Seedance 本地视频上传设计

## 目标

让本机运行的 Seedance 工作台支持直接选择 MP4/MOV 文件。后端自动把本地视频转换成 Seedance 云端能够拉取的临时公网 HTTPS 素材地址，任务结束后关闭通道并清理临时文件，同时继续支持现有的公网 HTTPS URL 和 `asset://` 素材 ID。

## 范围

本次功能覆盖视频参考模式和编辑视频模式。支持最多 3 个视频，每个视频 2～15 秒、最大 50MB。图片、音频、生成参数和历史任务行为保持不变。

不引入永久对象存储、用户账户、素材库管理或跨设备复用。临时地址只服务于当前本地工作台发起的生成任务。

## 方案选择

采用“独立临时素材服务 + Cloudflare Quick Tunnel”。工作台后端不直接暴露到公网；独立素材服务只响应带高熵令牌的具体视频路径，并仅允许 `GET` 和 `HEAD`。

未采用以下方案：

- 暴露整个工作台：实现简单，但扩大公网攻击面。
- 每个视频单独启动服务和隧道：隔离更强，但多视频任务会产生不必要的进程和隧道。
- 永久对象存储：稳定但需要额外账户、密钥和成本，不符合本机零配置目标。

## 用户体验

视频区域保留现有 URL 输入，并新增“上传本地视频”按钮。用户选择文件后，单条素材依次显示：

1. 正在上传；
2. 正在检查视频；
3. 正在建立安全通道；
4. 素材可用；
5. 失败时显示可操作的错误原因。

本地上传成功后，界面显示文件名、大小、时长和“移除”，不展示或要求用户复制临时公网 URL。用户仍可直接添加 HTTPS URL 或 `asset://` ID，二者可与本地视频混用，总数不超过 3 个。

## 架构

### 前端

`CreatorPanel.vue` 增加本地视频文件选择和上传状态。前端通过 multipart 请求把文件上传至新的后端接口，收到一个临时素材对象：

```json
{
  "upload_id": "opaque-id",
  "filename": "dance.mp4",
  "size": 12345678,
  "duration": 15.0,
  "status": "ready"
}
```

前端状态保存 `upload_id`，不保存临时公网 URL。创建生成任务时，将本地素材 ID 与现有视频 URL 分开提交。页面卸载不主动删除已经被任务使用的素材，避免中断云端拉取。

### 后端上传管理器

新增边界清晰的临时视频管理模块，负责：

- 流式接收文件并执行大小上限检查；
- 校验扩展名、MIME、文件魔数和实际媒体信息；
- 使用 `ffprobe` 读取时长、容器和视频流；
- 将文件保存到 `data/video_uploads/`，文件名使用随机 ID；
- 为素材分配 256 位随机访问令牌；
- 管理素材状态、引用任务和清理时间。

上传元数据持久化到 SQLite，保证后端重启后可以识别并清理遗留文件。数据库和 API 响应不保存临时公网 URL中的敏感令牌明文；令牌只在运行期映射中存在，重启后未完成上传标记为不可用并清理。

### 独立素材服务

素材服务绑定 `127.0.0.1` 的随机端口，只提供如下路径：

```text
/media/<256-bit-token>
```

行为限制：

- 仅允许 `GET` 和 `HEAD`；
- 支持标准 `Range` 请求，便于上游探测和分段拉取；
- 不提供目录列表、错误堆栈或真实本地路径；
- 令牌比较采用恒定时间比较；
- 响应包含正确的内容类型、长度和范围头；
- 其他路径和方法统一返回 404/405。

同一工作台进程共享一个素材服务和一个 Quick Tunnel。多个视频通过不同令牌隔离。

### 隧道管理器

后端在第一次本地视频上传时按需启动 `cloudflared tunnel --url http://127.0.0.1:<port>`，从进程输出读取 Quick Tunnel HTTPS 地址，并进行可用性检查。

可执行文件查找顺序：

1. 环境变量 `SEEDANCE_CLOUDFLARED_PATH`；
2. 系统 `PATH` 中的 `cloudflared`；
3. 项目管理目录中的已下载副本。

程序不会静默下载或运行新的可执行文件。找不到 `cloudflared` 时，上传接口返回明确配置错误，并继续允许用户使用公网 URL/`asset://`。安装和更新属于部署步骤，不属于运行期行为。

隧道异常退出时，所有依赖该隧道且尚未提交的素材标记为失败；已提交任务保留状态并提示上游可能无法继续拉取。后端可在有可用素材时尝试一次受控重启，域名变化后只更新尚未提交的素材，绝不更改已经提交给上游的任务地址。

## 任务数据流

1. 用户选择本地视频。
2. 前端上传至本地后端。
3. 后端流式校验并保存文件。
4. 后端启动独立素材服务和 Quick Tunnel。
5. 后端使用临时 HTTPS 地址执行一次 `HEAD` 自检。
6. 前端收到不透明的 `upload_id`，素材显示为可用。
7. 用户创建生成任务。
8. 后端在构造上游请求时，把 `upload_id` 解析为当前临时 HTTPS URL。
9. 后端记录本地素材与任务的引用关系。
10. 任务进入成功、失败或超时终态后释放引用。
11. 所有引用释放并经过短暂宽限期后，删除文件；没有剩余素材时关闭隧道和素材服务。

## 生命周期与清理

- 未提交素材：上传完成后 30 分钟过期。
- 已提交素材：至少保留到任务终态，再保留 5 分钟宽限期，防止上游延迟重试。
- 后端正常关闭：先停止接受新请求，再终止隧道和素材服务；磁盘文件留给下次启动清理。
- 后端启动：删除超过期限、缺少元数据或状态不一致的遗留文件。
- 用户点击“移除”：未被任务引用时立即标记待清理；已被任务引用时只从编辑表单移除，不中断任务。

清理操作是幂等的；文件已不存在或进程已退出都视为成功。

## 安全与隐私

- 上传接口沿用现有 Origin 校验，只接受本机工作台发起的写操作。
- 文件名不参与磁盘路径构造，避免路径穿越。
- 先流式限制 50MB，再运行媒体探测，避免超大请求耗尽内存或磁盘。
- `ffprobe` 使用参数数组调用，不拼接 shell 命令。
- 公网路径使用不可猜测令牌，不记录完整令牌或临时公网视频 URL。
- 素材服务只暴露目标视频字节，不暴露工作台、数据库、日志或其他本地文件。
- UI 明确提示：生成期间视频会通过临时 Cloudflare 通道提供给 Seedance/TokenHub 拉取。

## 错误处理

用户可见错误包括：格式不支持、文件超过 50MB、没有视频流、时长不在 2～15 秒、`ffprobe` 不可用、`cloudflared` 不可用、隧道建立超时、隧道自检失败和上传被取消。

失败不会把半成品素材加入表单。后端删除已写入的部分文件；如果其他素材仍在使用共享隧道，不关闭共享服务。

任务提交前，后端再次确认所有本地素材处于 ready 状态且隧道存活。若检查失败，拒绝提交并返回可恢复错误，不消耗生成额度。

## 配置

新增配置：

```text
SEEDANCE_MAX_VIDEO_BYTES=52428800
SEEDANCE_CLOUDFLARED_PATH=
SEEDANCE_VIDEO_UPLOAD_TTL_SECONDS=1800
SEEDANCE_VIDEO_POST_TASK_GRACE_SECONDS=300
SEEDANCE_TUNNEL_START_TIMEOUT_SECONDS=30
```

默认值适合单机使用。现有部署在不配置 `cloudflared` 时仍可使用原来的 URL/`asset://` 流程。

## 测试策略

后端测试覆盖：

- MP4/MOV 大小、魔数、视频流和时长校验；
- 超限上传在读取过程中中止；
- 随机令牌路由、`GET`、`HEAD`、`Range`、未知令牌和非法方法；
- 隧道启动、超时、异常退出和一次重启；
- 本地素材 ID 到上游 URL 的解析；
- 提交前就绪检查；
- 未提交过期、任务终态宽限和重启清理；
- 清理幂等及共享隧道不会被单个素材误关。

前端测试覆盖：

- 文件选择、上传进度和成功状态；
- 格式/大小的即时提示；
- 本地素材与 URL 素材混用及数量上限；
- 上传失败重试、移除和提交按钮状态；
- 创建任务时发送 `video_upload_ids`，不泄露临时公网 URL。

集成测试使用假的隧道进程和本地素材服务，不依赖真实 Cloudflare 或消耗 TokenHub 额度。最终人工验收使用一个短视频，确认 Seedance 能执行 `HEAD`/`GET`、任务能够提交、终态后文件和进程被清理。

## 验收标准

- 用户无需手工复制视频链接即可从本地选择并提交视频。
- Seedance 能通过自动生成的 HTTPS 地址读取完整视频。
- 原有 HTTPS URL 和 `asset://` 工作流不受影响。
- 任务提交前的失败不会消耗 TokenHub 生成额度。
- 任务终态后自动关闭不再使用的临时通道并清理视频副本。
- 公网无法访问工作台接口、目录列表或任何未授权本地文件。
